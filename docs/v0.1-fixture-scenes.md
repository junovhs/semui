# SEMUI v0.1 Fixture Contract

The canonical corpus is indexed by
`fixtures/v0.1/manifest.toml`. The manifest, not this document, is the
machine-readable source of truth.

Each scene must be static, locally renderable, small enough to diagnose, and
inside the supported subset. JavaScript, responsive breakpoints, animation,
external assets, and undeclared browser behavior are out of scope.

## Canonical scenes

1. `profile_card_absolute`: absolute coordinates, nested boxes, controls,
   borders, radius, paint, and typography.
2. `stacked_info_card`: column flex layout, spacing, text hierarchy, and pill
   styling.
3. `action_row_variants`: row flex layout, aligned controls, and visual
   variants.
4. `nested_panel_inset`: nested surfaces, border layering, padding, and
   independent radii.
5. `typography_specimen`: font family, size, weight, line height, width, and
   foreground color.
6. `update_toast`: combined column flex, absolute badge placement, control
   reset, border shorthand, and typography.

## Coverage expansion

The manifest also contains role-tagged fixtures that do not redefine the six
canonical scene identities:

- `supported_contract_micro` exercises every supported selector form,
  property, and value family in one minimal browser-proven scene.
- `settings_row_real` and `metric_tile_real` are minimized static scenes based
  on common production interface patterns.
- `unsupported_selectors_negative` covers every unsupported selector syntax
  family.
- `unsupported_declarations_negative` covers unsupported-property and
  unsupported-value diagnostics.

`fixtures/v0.1/coverage.json` is the machine-readable coverage matrix. Corpus
tests verify that each property and value mapping names a declaration that is
actually present, each selector mapping is exercised, all negative diagnostic
categories are represented, and every fixture declares six gate outcomes.

## Fixture requirements

Every fixture must provide:

- source HTML and CSS
- a manifest entry
- checked-in Scene IR and emitted HTML/CSS regression artifacts
- explicit expected diagnostics
- explicit expected proof outcomes once browser gates exist

Verification must never rewrite checked-in artifacts. Golden generation is a
separate maintenance operation.

Adding a fixture does not implicitly expand the supported subset. Any required
capability change must update the executable support policy and its governing
contract deliberately.
